## Project Overview

`ai-sourdough-starter` is a polyglot template repo that bootstraps new
projects with AI-assisted-development discipline baked in. It's not a
framework; it's a **starter culture** — a small set of files and hooks that,
once installed, enforce planning-before-coding, library-currency checks, CI
and coverage gates, and architecture decision records.

The starter itself is the product. Each profile (`go`, `java`, `nodejs-ts`,
`python`) is a fully-self-contained copier template.

## Architecture

```
ai-sourdough-starter/
├── AGENTS.md                          # canonical agent rules (the product's heart)
├── CLAUDE.md                          # this file — project-specific context
├── .clinerules/                       # Cline-specific addenda + synced workflows
├── .claude/
│   ├── settings.json                  # hooks + permission denylist (enforces rules)
│   ├── agents/                        # subagents
│   ├── commands/                      # SYNCED — edit agent-shared/, not this
│   └── hooks/                         # shell scripts called by settings.json hooks
├── agent-shared/commands/             # canonical slash-command bodies
├── profiles/
│   ├── _common/                       # files every profile gets (security CI, ADR seed)
│   ├── go/                            # FIRST PROFILE; pattern for the others
│   ├── java/
│   ├── nodejs-ts/
│   └── python/
├── bin/sync-commands                  # rebuild .claude/commands + .clinerules/workflows
├── bin/doctor                         # verify install integrity
├── docs/                              # philosophy, usage guides, hook design
└── tests/                             # tests of the starter itself (rendering tests)
```

## Conventions

- **Single source of truth**: `AGENTS.md` (universal rules) and
  `agent-shared/commands/` (slash commands). Never edit `.claude/commands/`
  or `.clinerules/workflows/` directly — they are regenerated by
  `bin/sync-commands`.
- **Profile independence**: each `profiles/<lang>/` directory must render
  cleanly on its own via `copier copy ... -a profiles/<lang>`. No
  cross-profile imports.
- **Templated paths**: Copier uses `{{ project_slug }}/` for the rendered
  output root; Jinja templates use `.jinja` suffix.
- **Cookiecutter compatibility**: each profile ships both `copier.yml` and
  `cookiecutter.json`; questions must match.

## Build, Test, Run

```bash
# Render the Go profile into a temp dir for testing
copier copy --trust . /tmp/demo-go -a profiles/go --data project_slug=demo

# Run the starter's own tests
pytest tests/

# Rebuild synced slash commands
bin/sync-commands

# Verify install integrity of the starter itself
bin/doctor

# Render a profile and run its CI locally
cd /tmp/demo-go && go test ./... && ./scripts/check-coverage.sh
```

## Gotchas

- **`AGENTS.md` is loaded inline by Claude Code's `@import`** — content
  changes there ripple into every session. Keep it tight; threshold for
  splitting into `.claude/rules/` is ~8 KB.
- **Cline does NOT support `@import`** in `.clinerules/`. Cline reads
  `AGENTS.md` natively, so we rely on that rather than trying to import.
  Don't add `@file` syntax to `.clinerules/*.md`.
- **Hook scripts must be executable** (`chmod +x`). The `post_gen_project.py`
  hook handles this on render, but if you copy hooks manually, set the bit.
- **`jq` is required by hooks**. `bin/doctor` checks for it.

## Key Files

- `AGENTS.md` — the rules; treat as a versioned API
- `.claude/settings.json` — the hook wiring; breakage here disables enforcement
- `.claude/hooks/require-plan.sh` — the plan-gate primitive
- `bin/sync-commands` — cross-tool bridge for slash commands
- `profiles/go/copier.yml` — the pattern other profiles clone
