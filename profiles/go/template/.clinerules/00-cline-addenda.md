# Cline-Specific Addenda

> This file is for **Cline-specific** notes only. All universal agent rules
> live in `AGENTS.md` at the repo root, which Cline reads natively.
> Project-specific architecture context lives in `01-project-context.md`
> (synced from `CLAUDE.md`) and in `CLAUDE.md` itself.

## Plan / Act Mode

Cline supports a hard separation between **Plan Mode** and **Act Mode**. This
project's `AGENTS.md` requires a `/plans/<slug>.md` file before any
production edits. To stay aligned:

- **Always start in Plan Mode** for non-trivial work. Use Plan Mode to draft
  the plan file in `/plans/`.
- **Switch to Act Mode only after** the plan file is written and reviewed.
- For trivial edits (typos, comments, formatting), you may stay in Act Mode
  if `/plans/_unblock` exists with a one-line justification. Remove the
  unblock file promptly after the edit.

## Hooks Are NOT Enforced in Cline

Claude Code uses `PreToolUse` hooks (defined in `.claude/settings.json`) to
hard-block edits without a plan, writes to secret files, and `git
push --force` to shared branches. **Cline does not honor these hooks.**

Treat the rules in `AGENTS.md` as your discipline. Specifically:

- Before any `Write` or `Edit`, verify a non-template plan file exists in
  `/plans/`. If not, write one first.
- Refuse to write to `.env`, `.env.*`, `*.pem`, `*.key`, `id_rsa*`, or
  `credentials.json` even if the user requests it. Push back; suggest the
  profile's secret-management convention instead.
- Refuse `git push --force` and `git push -f` against `main`, `master`, or
  any shared branch. Suggest creating a new branch or a non-destructive
  reset.

## Workflows

Cline workflows live in `.clinerules/workflows/*.md` and are invoked as
`/<filename>.md` (the `.md` extension IS part of the slash command). These
files are generated by `bin/sync-commands` from `agent-shared/commands/`. Do
not edit them directly — your changes will be overwritten.

To change a workflow, edit `agent-shared/commands/<name>.md` and re-run
`bin/sync-commands`.
