# Plan: v0.1.0 Bootstrap

> The starter dogfoods its own rules. This plan covers building the starter
> itself to v0.1.0 — the master plan lives at
> `~/.claude/plans/i-am-preparing-to-recursive-cherny.md`; this file is the
> in-repo pointer that satisfies the plan-gate hook.

## Problem statement

`ai-sourdough-starter` needs to be built to a usable v0.1.0 — a release that
can scaffold a green-CI project in any of four languages (Go, Java,
NodeJS/TS, Python) via `copier copy` (with cookiecutter compatibility).

## Non-goals

- Multi-template orchestration (one-shot installs of multiple profiles)
- Updates flow (`copier update`) — works mechanically, but no docs yet
- Distribution beyond `git clone` — no published package
- Cline workflow-specific tooling beyond the synced markdown files

## Proposed approach

Build in the sequence laid out in the master plan's "Implementation
sequencing" section:

1. Foundation: `AGENTS.md`, `CLAUDE.md`, `.clinerules/`, hooks, settings.json
2. Slash commands + sync script
3. Subagents
4. `profiles/_common/`
5. Go profile end-to-end
6. Test-rendering CI for Go
7. README + docs
8. `bin/doctor`
9. Java, TS, Python profiles
10. Tag v0.1.0

## Alternatives considered

- **One profile only at v0.1.0**: rejected because the user wants all four
  languages represented at first release.
- **Bash bootstrap instead of copier**: rejected during design — copier
  supports `update`, has wider scaffolder ecosystem, cookiecutter
  compatibility layer covers the legacy use case.

## Files to touch

The entire starter repo. See the master plan for the file tree.

## Test strategy

- `bin/doctor` for install-integrity smoke test
- `.github/workflows/test-rendering.yml` renders every profile and runs its
  CI in a matrix; this is the v0.1.0 acceptance test

## Rollback strategy

The repo is fresh and unpublished; v0.1.0 is the first tag. "Rollback"
before tag = `git checkout main`; after tag = `git revert <tag-commit>`.
